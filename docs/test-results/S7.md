## Fix found by (c)
`0 * facing(-1)` produced `-0` in `vx` (overload columns, zero-vx velocities, neutral jumps). JSON turns -0 into 0, so a
JSON round-trip differed from `structuredClone`. These writes now add `+ 0`.

## Interpretations made (spec silent; flag if wrong)
- The super freeze starts the frame after the super's frame 1 (set in `step` after the state machine).
- Super scale is stored on the attacker (`Fighter.superScale`, reset when a super starts) so projectile supers
  (overload columns, jadeDragon) and lockOnHit follow-ups share it. lockOnHit follow-ups now use it too (were unscaled).
- Multi-hit projectile freeze: frozen while the target started the step in hitstop and the projectile's cooldown still
  equals its `hitInterval` (i.e. it caused that hitstop); no new state field.
- Outside `fight` (intro, roundEnd, matchEnd) the state machine reads no input history: no moves, dashes, air jumps or
  techs (spec says inputs are fed as 0; requests read the history directly, so they are gated).
- KO is checked only in `fight`. A KO ends any lockOnHit sequence. Time over leaves the loser standing.
- Win pose: the round winner enters `win` once grounded and in idle/walk/crouch.
- Final round after 3 draws: any result ends the match; a draw there goes to higher raw hp, equal → P1.
- `matchEnd` keeps stepping with ignored inputs; only `phaseFrame` advances.
