## Interpretations
- Window = last N frames ending at the newest frame (ago 0..N-1). Each step uses its own frame (strictly older than the next).
  Spec says "at or after the previous one"; allowing a shared frame would make a single `3` satisfy qcf (2~3, 3, 6~3).
- Param named `frames` not `window` (lint bans the `window` identifier in shared).
- `5` in `dd` = any byte without DOWN. `spin` uses the tolerance table for 4/2/6; `8` exact.
- Charge: `chargeBack` counts held-back frames (capped 40); first non-back frame with full charge sets `chargeGrace = 10`,
  later non-back frames decrement it; `chargeReady` = full charge held or grace > 0. `resolveRequest` returns `charge` when ready and current dir is 6/3/9.
- `resolveRequest(f, facing)` covers motion priority only (dqcf → spin → dp → qcf/qcb most-recent-final-step, tie qcf → charge → dd); button buffer, throw and normals stay in the sim (S4+).
